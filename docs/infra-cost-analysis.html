Recommendation

Supabase (managed Postgres + Auth + file storage, one bill) for the database and login system, Cloudflare R2 for card photos, Upstash Redis for live auction/bid state. The Go backend (apps/api) connects straight to Supabase's underlying Postgres with a normal connection string and verifies its JWTs — it never goes through Supabase's client SDK. That keeps every table Go touches (wallet ledger, escrow, listings) in one real Postgres database, with login/signup handled by a system that's already been through more security review than a first-pass custom auth flow would get.

Cost: roughly $0–15/mo while building, $45–60/mo at a few thousand users, $165–380/mo at a real 30,000-user marketplace. Full math below.

“Like eBay” isn't a pricing tier

eBay doesn't rent a database plan — it runs its own data centers, thousands of database instances, and dedicated infrastructure teams, inside a technology budget that's a multi-billion-dollar annual line item in its public filings. Raw hosting is one small piece of that, not something priced separately anywhere. That's a different kind of problem (build-and-staff-your-own-infrastructure-org) than the one in front of you right now (which managed Postgres tier), so it isn't a usable benchmark to size AuctionHous against. The table below prices the problem you actually have: a TCG marketplace at three realistic points on its growth curve.

Why the totals diverge

Every vendor here prices Postgres, Redis, and storage in roughly the same shape: pay for the compute/storage/bandwidth you actually use. Auth is the odd one out — some vendors charge per user, and that bill scales with your growth in a way the others don't.

AWS Cognito's default (“Essentials”) tier bills $0.015 per monthly active user after the first 10,000 free. At 30,000 users that's 20,000 billable × $0.015 — $300/month for login alone, and it keeps climbing linearly with every user you add. Clerk flattens this with a $100/mo plan that includes 50,000 users, so it doesn't bite until you're past that line. Supabase goes further and folds auth into the same flat plan as the database itself — up to 100,000 monthly active users are already covered by the $25/mo Pro plan you'd need for the database anyway. For a marketplace whose whole pitch is a thin 2% fee, paying a growing per-user tax just to let people log in is the wrong shape of cost to take on.

The actual recommendation

Database + login: Supabase. It's still plain Postgres underneath — the Go backend connects with a normal DATABASE_URL and runs the same migrations already sitting in apps/api/migrations. Nothing about the wallet ledger, escrow, or listings tables changes. Supabase Auth issues a JWT on signup/login; the Go API's internal/platform middleware verifies that JWT on incoming requests instead of implementing session/password logic itself. Email verification, password reset, and rate-limiting on auth endpoints come from a system with far more security scrutiny on it than a first version we'd write ourselves.

Card images: Cloudflare R2, as the design doc already specified — its zero-egress pricing matters specifically because listing photos get viewed far more often than they're uploaded.

Auction/bid state: Upstash Redis, matching the design doc's Redis requirement for live auction timers and wallet locks, without managing a Redis instance by hand.

Exit ramp, if you ever need one: because Supabase Auth's user table lives inside the same Postgres instance, moving off it later is a data migration, not a rewrite — export the user list, re-hash or force a password reset, and point the Go API at a self-rolled auth flow. That's a real project if it ever comes to it, but it's never a rewrite of the marketplace itself.
